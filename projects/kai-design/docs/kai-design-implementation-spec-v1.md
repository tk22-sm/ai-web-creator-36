# Kai Design 実装仕様書 Ver.1

- ステータス：実装前の基準仕様（未決定事項あり）
- 作成日：2026-10-27
- 目的：Claude Code等への実装引き継ぎ、自己学習、SNS・note向け制作記録

## 1. プロジェクトの目的
1. Web制作案件の獲得：企業・店舗・個人事業主等へ制作力と信頼性を示し、相談につなげる。
2. 技術力の提示：SES営業担当・技術担当者へ実装力、技術選定、コード管理力を伝える。
3. 学習発信と収益化：制作過程をSNSで発信し、noteの無料記事・有料教材へつなげる。

2026年内の初期公開を優先する。ブランド名「Kai Design」は仮称。個人によるWeb制作活動であり、法人であると誤認させない。

## 2. 事業の対象と表記
- Webサイトの新規制作、HTML/CSS/JavaScriptによるコーディング、レスポンシブ対応、既存サイトの軽微な修正・改善を中心とする。
- React、Next.js、TypeScriptはWebサイト制作に活用する技術として掲載する。大規模Webシステム開発を提供サービスに含めない。
- 2021年4月からの業務システム開発・設計・テスト経験、2026年4月以降の要件定義・テスト推進等の経験はAboutの経歴として扱う。顧客の機密情報は記載しない。
- UI/UXデザインスクールで6か月学習・制作し、Figma、Illustrator、Photoshopを使用した経験を掲載する。現在の熟練度を誇張しない。
- 日本語を主言語とし、英語は見出しやブランド表現の補助に限定。操作ボタン、フォーム、エラー文言は日本語。

## 3. コンテンツ分類
- Projects：自主制作。架空企業・架空店舗であることを明示。
- Works：実際の受託制作のみ。初期公開時はページ・ナビゲーションを作らない。掲載許可のある案件ができたら追加。
- Products：MY SOLO等、本人が企画・開発するWebサービス。公開可能になった時点で独立した分類として追加。
- Case Study：作品詳細内の企画・設計・実装・検証・振り返り。
- What I Can Do：依頼者に提供するWeb制作の範囲。独立したServicesページは初期版では作らずAboutに掲載。

## 4. サイトマップ
- `/`：Home
- `/projects`：自主制作一覧
- `/projects/[slug]`：作品詳細
- `/about`：経歴・スキル・対応可能な制作
- `/contact`：問い合わせフォーム
- `/privacy`：個人情報の取り扱い

初期トップページの順序：Hero → Selected Projects → Approach → About → Journal → Contact。
Journalはnote記事の紹介セクションであり、独自ブログ/CMSは作らない。ナビゲーションは「制作実績」「私について」「学習・制作記録」「お問い合わせ」を基本とし、学習・制作記録はホーム内Journalへ誘導する構成を第一候補とする。

## 5. デザインシステム
- コンセプト：Minimal × Creative × Purposeful Motion。
- 背景：`#111214`、サーフェス：`#1C1E22`、メイン文字：`#F5F5F2`、アクセント：`#7CECC0`、ホバー：`#A6F4D7`。
- アクセントは控えめに使用。本文・補助文字色はコントラストを検証して確定。
- 最大コンテンツ幅：約1200px。左右余白：PC 48–64px、スマホ20–24px。セクション間隔：PC約120px、スマホ約72px。カード角丸8–12px。数値は実装時に検証・調整。
- フォントは日本語の可読性を優先し、英語見出しとの組み合わせを選定する（未確定）。

### レスポンシブ
- Hero：PCは大きなテキスト左＋代表作品ビジュアル右。スマホはテキスト上＋画像下。
- Selected Projects：PCは2列を基本としたコンパクトなカード、スマホ1列。作品数の増加に備え一覧ページを別に設ける。
- Approach：PC3列、スマホ縦積み。
- About：PC2列を基本、スマホ1列。
- Journal：PC2〜3記事、スマホ縦積み。
- Contact：スマホでも操作しやすいフォームとCTA。

### 動き
- Hero：フェード＋軽いスライド、目安0.5〜0.8秒。
- スクロール時の要素表示：目安0.5〜0.7秒。表示されないまま取り残さない。
- 作品画像ホバー：拡大率目安1.03、約0.4秒。
- ボタン：色や矢印の小さな変化、約0.2秒。
- `prefers-reduced-motion` に対応。キーボードフォーカスを明示。不要なアニメーションライブラリは導入しない。

## 6. Homeの各セクション
### Hero
- 英語コピー案：`Design with purpose.`
- 日本語コピー案：`伝えるべきことを、伝わるデザインに。`
- 説明文：サービスの背景や価値を理解し、必要な人へ伝えるWebサイト制作。
- CTA：`制作実績を見る`、`お問い合わせ`。
- 代表作品の実際の画像を使用。架空の成果指標は表示しない。

### Selected Projects
- 初期掲載：株式会社 木と日々、MELLOW COFFEE。
- 「自主制作」「架空企業／架空店舗」を明示。
- 一覧への導線：`自主制作一覧を見る`。

### Approach
- 主コピー：`想いを理解し、価値を見つけ、必要な人へ届ける。`
- 3段階：Understand（背景と想い）→ Discover（市場・競合・強み）→ Deliver（適切な人へ価値を届ける）。
- 理念として説明する。実案件で実施した調査・成果と誤認させない。

### About
- トップは要約、`詳しいプロフィールを見る` で `/about` へ。
- 詳細ページはProfile、Experience、Skills、What I Can Doの4領域。

### Journal / 学習・制作記録
- おすすめまたは新着note記事を最大3件。記事タイトル・分類・日付・画像（ある場合）を手動登録。
- 記事およびnoteプロフィールへ外部リンク。公開済みURLのみ掲載し、未公開記事は表示しない。
- noteの販売コンテンツは再現可能な手順・コード・設計資料等を中心にする。作品理解に必要な説明はサイト内で無料公開。

### Contact
- `/contact` へ誘導。サイト内のCTAは日本語。

## 7. Projects詳細テンプレート
1. Overview：作品名、概要、自主制作区分、技術、公開サイト。
2. Background：制作の背景、想定課題。
3. Research：実施した調査、想定ターゲット。仮説と実査を明確に区別。
4. Design：情報設計、色、余白、レイアウト、採用理由。
5. Development：使用技術、機能、実装の工夫。
6. Quality：表示確認、アクセシビリティ、SEO、検証結果。
7. Reflection：学び、課題、改善予定。
8. Links：公開サイト、公開可能なGitHub、公開済みnote。

各作品で実際に存在する内容だけ表示。未実施の調査・架空の実績・未計測の数値を作らない。

初期作品：
- 木と日々：架空住宅会社の複数ページサイト。Next.js / React / TypeScript。公開URL `https://ki-to-hibi.pages.dev`。情報設計、複数ページ、品質確認を重点紹介。問い合わせはデモで送信されないことを明示。
- MELLOW COFFEE：架空カフェのLP。HTML / CSS / JavaScript。公開URL `https://mellow-coffee.pages.dev`。世界観、ビジュアル、LP構成、レスポンシブを重点紹介。

両サイトの演出・改善は今後行う計画。改善完了前に完了済みとして記載しない。

## 8. Contactの実装
- Formspreeを採用。サイト本体はNext.js静的サイトとしてCloudflare Pagesに公開。
- 必須：お名前、メールアドレス、ご相談内容。
- 送信中表示、送信成功／失敗の日本語メッセージ、入力チェック、二重送信防止、失敗時の入力保持。
- Formspree側のフォームID／送信先は環境別に管理。秘密情報をGitにコミットしない。公開される設定値と秘密値の違いを確認。
- スパム対策、受信通知、受信メールの管理、送信件数上限を導入時に最新公式仕様で確認。
- `/privacy` には取得情報、利用目的、第三者サービス利用、保管・問い合わせ先等を実態に合わせて記載。法的な最終確認が必要。
- 公開前に実送信テスト、エラー時の挙動、スマホ表示、通知到達を確認。

## 9. 技術とディレクトリ
- Next.js App Router / React / TypeScript
- CSS Modules + 共通CSS（初期案）
- CSS主体のアニメーション
- `output: 'export'` を基本とした静的書き出し。動的ルートは `generateStaticParams` など静的出力の条件を満たすよう実装。
- Cloudflare Pagesで `out` を配信する構成を第一候補とする。利用時の最新互換性を確認。
- Git / GitHub
- 独自DB、CMS、独自ブログ、独自メール送信サーバーは初期版で不要。

## 10. ソースコードコメント規約
- 主要な関数・コンポーネントに日本語で役割を説明。
- 重要な引数・戻り値・データの流れ・ファイル間の依存関係・設計理由を必要に応じて記載。
- API連携、フォーム処理、エラー処理、静的生成の条件は特に明確にする。
- コードを読めば分かる行単位の説明や、処理とずれた古いコメントは避ける。
- 実装ステップごとに「変更ファイル」「主要処理の流れ」「採用理由」「学習ポイント」「検証結果」を日本語で報告。

## 11. 開発順序
1. プロジェクト基盤、Git、共通CSS、フォント、レイアウト。
2. Homeの6セクション。
3. Projects一覧、作品データ、詳細テンプレート。
4. About、Contact、privacy、Formspree。
5. レスポンシブ、動き、細部調整。
6. SEO、OGP、アクセシビリティ、フォーム送信確認、Cloudflare公開。

各ステップ終了時に動作確認・差分レビュー・意思決定ログ更新を行い、次工程へ進む。

## 12. 公開前チェック
- PC／スマホ表示、全ページと全リンク、404への対処。
- フォームの入力チェック、実送信、通知、エラー、二重送信防止。
- 日本語で理解できる導線と文言。
- 架空作品と実案件の区別、機密情報・無許可素材の不使用。
- 画像最適化、alt、見出し構造、キーボード操作、色コントラスト、reduced motion。
- ページ別title／description、OGP、SNS共有時の表示。
- Lighthouseなどによる速度・アクセシビリティ確認（スコアのみを合否基準にしない）。
- GitHubと公開環境に秘密情報を含めない。

## 13. SNS・note向け記録ルール
各工程で次を記録：
- 何を作ったか、何を学んだか。
- 比較した案、採用・不採用理由。
- つまずき、エラー、修正、検証。
- スクリーンショットやコードの再利用可否。
- SNS短文の切り口、無料noteのテーマ、有料教材化できる再現手順。

基本導線：SNSで学びを1つ提供 → noteで詳しい解説 → 必要に応じてKai Designの制作実績へ。Kai DesignのJournalからもnoteへ誘導。投稿頻度・販売価格は反応を見て決める。

## 15. Claude Codeへの実装指示
- この仕様書を基準とし、まずリポジトリ状況を調査し、差分と実装計画を提示する。
- 既存の他作品・既存サイトを破壊しない。秘密情報を表示・コミットしない。
- 仕様外の大規模機能、CMS、DB、重いライブラリを勝手に追加しない。
- 1ステップずつ実装し、ビルド／型チェック／動作確認の結果を報告する。
- 主要処理には日本語コメントを入れ、変更したファイル、データフロー、理由を説明する。
- 自主制作・架空企業表記を維持し、未実施の調査・成果を創作しない。
- 実装中に必要となった仕様変更は、選択肢・理由・影響範囲を示して確認する。
