# Kai Design 個人情報の運用ルール

お問い合わせで受け取る個人情報を、運営者がどう扱うかの手順書（D-062）。
プライバシーポリシー（`app/privacy/page.tsx`）の「保存期間と削除」「開示・訂正・削除のご依頼」は、この手順を前提に書いている。

- このファイルには、個人情報・実際のメールアドレス・フォームID・パスワードなどの認証情報を書かない。
- 法的な判断が必要な点は「要法務確認」と書き、推測で決めない（公開前チェックリスト A1）。
- 内容を変えたときは、プライバシーポリシーと decision-log も合わせて更新する。

---

## 0. 管理できる範囲

| 運営者が管理できる範囲 | サービス提供者が保持する範囲（運営者は直接削除できない） |
|---|---|
| 専用 Gmail の受信トレイ・送信済み・ゴミ箱・迷惑メール・下書き・ラベル | Google が保持するバックアップ・記録（ログ） |
| Formspree の管理画面で削除できる送信内容（少なくとも Over Limit フォルダは削除できることを公式で確認済み） | Formspree のバックアップ・記録、30日経過後の扱い（公式で未確認） |
| （開設後）SNS の DM の自分側の表示 | SNS 運営会社が保持するデータ、相手側に残る DM |
| 手元の対応記録（個人情報を書かないもの） | Cloudflare が処理する通信に関する情報 |

右側の範囲について、削除を保証する説明はしない。

## 1. 使うアカウントと保護

| アカウント | 用途 | 保護 |
|---|---|---|
| Kai Design 専用 Gmail | Formspree の通知の受信、お問い合わせへの返信 | 2段階認証（設定済み）、転送・自動バックアップは使わない、パスワードは使い回さない |
| Formspree | フォームの受け付け・保存・通知。ログイン用のメールアドレスは従来のもの（専用 Gmail とは別） | 2段階認証を設定する（公開前チェックリスト A3。認証アプリ方式のみ対応）、バックアップコードを安全な場所に保管する |
| Cloudflare・GitHub | サイトの配信・ソースの管理 | 2段階認証（A3） |

- 専用 Gmail の通知先は、テスト用フォームで変更・確認済み。本番用フォームを作るときも、通知先を専用 Gmail にする（A7）。
- Formspree の通知先として登録するメールアドレスは、専用 Gmail だけにする。
- 問い合わせの内容・お名前・メールアドレスを、AI ツールやほかのサービスに貼り付けない。
- Formspree のプラグイン・外部連携・書き出し（CSV・JSON）は使わない。

---

## 2. 問い合わせの受け付けから対応終了まで

1. Formspree から専用 Gmail に通知メールが届く。
2. 迷惑な送信かどうかを判断する。迷惑な送信なら、Gmail と Formspree の両方から削除する。
3. 通知メールの返信先（Reply-To）に返信する。引用は必要な範囲だけにする。
4. やり取りが続いている間は、Gmail のラベル「対応中」を付ける。
5. 対応が終わったら、ラベルを「対応終了」に変える。
6. Formspree の管理画面で、その送信内容を削除できる範囲で削除する（3章）。
7. ご依頼につながった場合は、契約・請求に必要な情報だけを別の管理場所に移す（7章）。

---

## 3. Formspree の保存・削除

- 対応が終わったら、管理画面の受信箱（Inbox）・迷惑メール（Spam）・上限超過（Over Limit）のうち、削除できる場所から速やかに削除する。
- 公式で確認できた仕様（2026-11-08 時点）：
  - 無料プランは「30日分の送信履歴を保存」（Account limits）。
  - Over Limit フォルダの送信は削除できる。削除は元に戻せない（Over limit submissions）。
  - 書き出しは有料プランのみ。
- 未確認の仕様：受信箱・迷惑メールで1件ずつ削除できるか、30日経過後に削除されるのか表示されなくなるだけか、バックアップ・記録の保存期間、保存場所の国。
  - 管理画面を確認するときは、読み取りだけにとどめ、確認した結果をこの章と decision-log に記録する。
  - Formspree サポートへの問い合わせは、現時点では行わない（運営方針）。
- プライバシーポリシーでは、契約しているプランに依存する説明（無料プランの30日分の保存など）は書かず、「Formspree 上の情報の保存・削除は同社の仕様・方針による」としている。30日経過後の削除を保証する説明はしない。
- 削除できない場合でも、プライバシーポリシーは「削除できる範囲で」としているため、運用と表示は矛盾しない。
- プランを変更した場合は、この章の「公式で確認できた仕様」を確認し直す。

## 4. 通知・返信メールの削除（最後のやり取りから3か月以内）

- **対象**：受信トレイ・送信済み（自分の返信と引用）・迷惑メール・下書き・ゴミ箱。
- **起算日**：そのやり取り（スレッド）で、最後にメールを受け取った日と、最後に送った日のうち、遅いほうの日。相手から新しい連絡があれば、その日が新しい起算日になる。
- **削除の手順**：スレッドを削除し、ゴミ箱からも完全に削除する。

### 4-1. 期限の管理方法

- Gmail のラベルで状態を管理する。
  - 「対応中」：やり取りが続いているスレッド。
  - 「対応終了」：回答が終わったスレッド。
- 月1回の点検（6章）で、**最後のやり取りから2か月以上経ったスレッドを削除する**。2か月で削除の対象にするのは、点検の間隔（1か月）を考えて、3か月の期限までに余裕を持たせるため。
- 探し方の例：Gmail の検索で、ラベルと期間（例：`older_than:2m`）を組み合わせる。検索結果のスレッドを開き、起算日（最後のやり取りの日）を確かめてから削除する。
- 点検の日はカレンダーなどの通知で忘れないようにし、点検した日と削除した件数（個人情報を含めない）を記録する。
- この運用は、点検が予定どおり行われることを前提にしている。点検が遅れれば3か月を超えるおそれがあるため、次の「点検が遅れたとき」の対応をとる。

### 4-2. 点検が遅れたとき

- 予定日に点検できなかった場合は、できるだけ早く点検を行う。
- 点検の際に、最後のやり取りから3か月を超えたスレッドが見つかった場合は、その場ですぐに削除する。
- 期限を超えたことと、その原因（例：点検日の失念）を記録し（個人情報は書かない）、点検日の通知の見直しなど、再発を防ぐ対策をとる。
- 遅れが繰り返される場合は、削除の対象を「2か月以上」より短くする、点検を月2回にするなど、運用を見直す。

### 4-3. 対応中の問い合わせの扱い

- 「対応中」のスレッドも、起算日は最後のやり取りの日で数える（ラベルが「対応中」でも、期限は延びない）。
- 点検の際に、最後のやり取りから2か月以上経った「対応中」のスレッドがあれば、次のどちらかにする。
  - やり取りが止まっている場合：対応を終えたものとして扱い、削除する。相手から改めて連絡があれば、新しいやり取りとして対応する。
  - ご依頼（契約）につながった場合：契約・請求に必要な情報だけを契約管理の場所に移してから（8章）、問い合わせのスレッドを削除する。
- 3か月を超えて残す必要がある情報は、問い合わせの記録としてではなく、契約・請求の情報として、別の保存ルール（8章）で管理する。

### 4-4. 削除依頼があった場合

- 期限を待たずにすぐ削除する（5章）。

## 5. 本人からの開示・訂正・削除の依頼

1. **受け付ける**：お問い合わせフォームから受け付ける（SNS の DM は開設後。8章）。
2. **本人を確認する**：元のお問い合わせのメールアドレス宛てに確認のメールを送り、その返信で本人と確認する。
   - 違うメールアドレスからの依頼は、元のメールアドレスから連絡してもらう。
   - 追加の本人確認書類は求めない。
3. **探す**：専用 Gmail（全フォルダ）、Formspree の管理画面（受信箱・迷惑メール・Over Limit）、手元の対応記録。
4. **対応する**：
   - 開示：保有している項目（お名前・メールアドレス・ご相談の種類・ご相談内容・やり取りの有無）を伝える。
   - 訂正：直す。
   - 削除：削除できる範囲をすべて削除する。
   - Formspree などで運営者が削除できない部分があれば、そのことを伝える。
5. **結果を伝える**：対応した内容を返信する。依頼のやり取りのメールも、4章のルールで削除する。
6. **記録する**：日付・依頼の種類・対応結果だけを記録する（お名前・メールアドレス・内容は書かない）。
7. **対応期間**：遅滞なく対応する。具体的な日数は運営者が決める（要法務確認）。

---

## 6. 月1回の点検

毎月、決めた日に行い、点検した日と結果（個人情報を含めない）を記録する。

- [ ] Formspree：受信箱を確認し、対応済みの送信が残っていれば削除する
- [ ] Formspree：迷惑メールのフォルダを確認し、本物のお問い合わせが紛れていないか確かめる。不要なものは削除する
- [ ] Formspree：Over Limit フォルダを確認する（月50件の上限を超えた送信は、通知されずにここに入る）。必要なものは翌月に再処理し、不要なものは削除する
- [ ] Formspree：当月の件数と、使用量の通知（50%・75%・90%・超過）が届いていないか
- [ ] 専用 Gmail：最後のやり取りから2か月以上経ったスレッド（「対応中」を含む。4-3）を削除し、ゴミ箱からも削除する
- [ ] 専用 Gmail：3か月を超えたスレッドが残っていた場合は、すぐ削除し、原因と対策を記録する（4-2）
- [ ] 専用 Gmail：迷惑メールのフォルダに、通知メールが紛れていないか
- [ ] 専用 Gmail・Formspree：2段階認証が有効か、見覚えのないログインが無いか
- [ ] （開設後）SNS の DM：4章と同じルールで削除する

## 7. 障害・上限超過・迷惑な送信のとき

- **通知メールが届かない**：Formspree の管理画面で受信状況を確かめ、Gmail の迷惑メールのフォルダも確認する。
- **Formspree の障害が続く**：必要に応じて、本番環境のフォームIDを外して再デプロイし、フォームを「準備中」の表示にする（公開後の手順）。
- **上限超過**：上限を超えた送信は通知されず、Over Limit フォルダに保存される。月の件数が戻ったら再処理して対応するか、削除する。
- **迷惑な送信**：確認したらすぐ削除する。大量に届く場合は、公開前チェックリスト A10 の手順に従う。
- **漏えいが疑われる**：公開前チェックリスト A9 の初動対応に従う。

## 8. 契約・請求の情報との区別

- お問い合わせのやり取り（4章の3か月ルール）と、契約書・請求書・取引の記録は、保存場所と保存ルールを分ける。
- ご依頼が決まった時点で、契約・請求に必要な情報だけを契約管理の場所に移す。問い合わせのスレッド自体は、4章のルールで削除する。
- 契約・請求の情報の保存期間（法令上の保存義務の有無を含む）は、別途決める（要法務確認）。

## 9. SNS の公式アカウントを開設するときに追加する作業

開設するまでは、存在しない窓口をサイトに表示しない。

1. SNS のアカウントに2段階認証を設定する。
2. プライバシーポリシーに、SNS の DM で受け付ける情報の取り扱い（運営会社が保存すること、相手側に残ること）を追加する（要法務確認）。
3. この手順書に、DM の保存・削除（4章と同じ3か月ルール）と、DM での本人確認の方法を追加する。
4. DM では住所・電話番号などを聞かず、詳しい内容はフォームへ案内する方針をプロフィールなどに明記する。
5. サイトから公式アカウントへリンクし、なりすましと区別できるようにする。
6. 月1回の点検に、DM の確認を加える（6章）。

## 10. 法務確認が必要な事項（公開前チェックリスト A1）

- Formspree・Gmail（Google）・Cloudflare それぞれの役割を、個人情報保護法上どう位置づけるか（委託か、第三者提供か、取り扱いに当たらないか）。プライバシーポリシーの第5章は、この結論が出るまで「確認中」の書き方にしている。
- 国外の事業者への提供（移転）について、本人への情報提供（国の名称・その国の制度・提供先の措置）と同意の方法。
  - フォームの「個人情報の取り扱いに同意します」の確認欄が、国外への提供に必要な同意に当たるかは**未確定**。足りるとは扱わない（プライバシーポリシーの第5章でも「確認中」と明示している）。
  - 同意が必要と判断された場合は、確認欄の文言・確認欄の近くでの説明・プライバシーポリシーの記載を合わせて見直す（コードの変更を伴う可能性がある）。
- 各サービスの事業者の所在国と、保存場所の国（Formspree は公式で未確認）。
- 保存期間の書き方（3か月以内・削除できる範囲で速やかに・サービス提供者が保持する範囲）が適切か。
- 運営者として公表すべき事項（氏名・住所などの範囲）と、安全管理措置の公表。
- 開示・訂正・削除の請求への対応期間と、本人確認の方法。
- 契約・請求の情報の保存期間。
- SNS の DM を窓口に加える場合の記載。
